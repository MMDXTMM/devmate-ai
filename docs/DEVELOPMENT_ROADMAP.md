# 分阶段开发路线

## 总原则

每个阶段都要同时满足：

1. 能运行。
2. 有自动化测试或可重复验收步骤。
3. 能解释设计取舍。
4. 不提前引入下一阶段的复杂组件。

## 阶段 0：基础工程（当前）

目标：任何一台安装 JDK 的电脑拉取仓库后都能启动。

- Spring Boot 基础工程
- Maven Wrapper
- 统一响应与全局异常
- H2 零配置启动
- MySQL 本地配置模板
- Flyway 数据库迁移
- 健康检查和基础测试

验收：

```bash
./mvnw test
./mvnw spring-boot:run
curl http://localhost:8080/api/health
```

## 阶段 1：项目管理业务闭环

目标：先建立 Agent 未来可以操作的真实业务对象。

- 项目新增、查询、修改、删除
- DTO 参数校验
- MyBatis-Plus 数据访问
- 分页、逻辑删除和审计时间
- 统一错误码
- Controller 与 Service 测试
- OpenAPI 接口文档

验收：可以通过 API 创建和管理一个待分析的 Java 项目。

## 阶段 2：源码导入与结构化解析

目标：从指定目录或上传压缩包中安全提取 Java 项目结构。

- 项目文件白名单
- 路径穿越防护
- 文件大小和数量限制
- Java 文件扫描
- 类、方法、包、路径等元数据提取
- 原始文件指纹
- 索引任务状态

验收：导入一个示例项目后，可查询文件与符号清单。

## 阶段 3：第一版代码 RAG

目标：用户问题能检索到相关源码片段。

- 代码语义切片
- Embedding 接口抽象
- 向量存储接口抽象
- Top-K 检索
- 项目、分支、提交版本过滤
- 关键词与向量混合检索
- 可复现的检索评测问题集

验收：对预设问题，相关代码片段能够稳定出现在前 K 个结果中。

## 阶段 4：问答与引用

目标：模型基于检索内容回答，并明确引用来源。

- 模型客户端抽象
- Prompt 模板
- 上下文预算控制
- 流式或普通问答
- 文件、类、方法引用
- 无证据时拒绝编造
- Token 与耗时记录

验收：回答“登录流程在哪里”时能给出正确源码引用。

## 阶段 5：Agent 与 Tool Calling

目标：从固定 RAG 流程升级为受控任务编排。

- `searchCode`
- `searchKnowledge`
- `analyzeStackTrace`
- `analyzeProjectStructure`
- 工具参数校验
- 最大调用步数
- 工具超时和失败处理
- 工具调用审计

验收：异常分析任务会自动选择堆栈解析和代码检索工具，并生成有依据的结论。

## 阶段 6：增量索引与异步任务

目标：源码变化后以较低成本更新知识库。

- Git diff / 文件指纹判断
- 删除旧 Chunk
- 只重建变更文件
- RabbitMQ 异步任务
- 幂等键
- 失败重试与死信
- 任务进度和结果通知

验收：修改单个文件后，不触发全项目重新 Embedding。

## 阶段 7：认证、权限与可观测性

- Spring Security + JWT
- 用户、项目成员和角色
- 项目级数据隔离
- Redis 限流与会话
- 指标、结构化日志和追踪
- Prompt 注入防护
- 敏感数据脱敏

验收：无权限用户无法检索其他项目源码；模型异常不会拖垮普通业务接口。

## 阶段 8：部署和演示

- Docker 镜像
- 测试环境数据库
- Nginx
- 环境变量与密钥管理
- 自动迁移
- 备份与恢复演练
- 演示数据与面试讲解

## 阶段 9：按真实需求拆分服务

先观测再拆分。候选：

- Agent：调用模型慢、需要独立限流和扩容。
- Knowledge：解析和索引资源消耗高。
- Web 业务：保持稳定、低延迟。

拆分时再引入 Gateway、注册发现、配置中心和远程调用，不把“使用微服务”本身当作目标。
