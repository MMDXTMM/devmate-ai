# 跨语言项目通俗理解：论文方法与可复验证据

日期：2026-11-13。本文记录本轮实际实现与验收，可用于论文的系统设计、实现和测试章节。它不是用户研究、准确率报告或目标仓库运行证明。

## 研究问题与方法

基础较弱的读者需要先理解用途、能力模块和一件事的处理逻辑，再决定深入哪里。现有Java技术入口、全量类清单或长篇架构报告难以直接回答这些问题。本系统将解释工作流与语言结构解析分开：通用Skill规定调查和解释步骤，宿主负责安全索引、版本、预算、证据和状态。

处理链路为：授权Git快照 → 白名单文本/Java AST索引 → README与清单侦察 → 运行源码优先有界取样 → 模型归纳用途/能力/流程 → 引用和结构校验 → 三层导览 → 同版本检索问答与证据续读。

可讨论的工程设计贡献如下；不据此宣称学术首创：

1. **解释协议与解析器分离**。通用能力归纳不预设Controller、数据库或Web架构；Java保留AST，其他已支持文本类型降级为有行号的片段。二进制、混淆、外部缺失服务不猜测。
2. **宿主管理证据**。模型只引用本轮短ID，Java映射回真实Chunk，校验状态、步骤、模块和引用；文件、revision、位置、预算来自宿主。报告/会话保存指针，阅读时回填，避免复制源码。未读取与部分实现分开。
3. **渐进解释和按需核对**。先用途/模块/一条流程，再看一件事，再看源码。实现来源、未执行测试、文档和配置分开标注；引用可定位，截断可续读。业务模块与Java入口仅在共享证据时建立对应。
4. **明确目标优先检索**。识别路径和符号，区分定义与引用，精确目标不继承旧主题；中文业务可使用当前用户同版本报告作线索。LOCAL代码哈希仅是确定性特征，不等同语义模型。
5. **可观察的模型边界**。显式生成、付费提示、持久化状态、幂等与短事务；模型不执行任意Shell/SQL。结构化分支使用可空下一步表达终止，读取旧报告不伪造新分支。

实现保持Java/Vue模块化单体与MySQL，没有新增微服务、消息中间件或数据库。

## 实验设置与样本

同一Agent模拟用户、教师、开发者三个视角，修改前后比较同一Git快照和相同问题。没有招募真实师生，不用Agent阅读速度替代学习成绩。

| 样例 | 固定revision | 本轮用途 |
|---|---|---|
| `pallets/itsdangerous` Python库 | `672971d66a2ef9f85151e53283113f33d642dabd` | 无Java导览、核心取样、Signer精确追问、证据语言与续读 |
| `MMDXTMM/GastronomicCheck---inSystem` Java业务项目 | `d5bce026d5a894ae552d417b997fe7ada765f5e2` | 中文业务检索、接口到实现、条件分支、历史任务说明 |

DevMate在本机MySQL运行，使用联调账号已有兼容API与`gpt-6.1-sol`。没有运行这两个目标项目或它们的测试。本轮没有重新导入或重建目标索引，因此修复前后输入版本可比；模型生成非确定，单次耗时只描述该次观察。

配置：`project-guide-v7`、`runtime-first-v4/text-excerpts-v1`、`lexical-graph-v2`；取证最多40片段/48000字符，单文件最多两个片段（主要README最多四个）。Java使用原AST，通用文本最多检查16个候选。检索对照TopK=8、预算8000，HYBRID在无可用向量时按响应如实降级。

这三题是针对已发现故障的诊断集，存在选题偏差；不能计算或宣传“任意项目准确率”，也不是独立盲测或检索算法全面优于其他产品的证明。

## 真实生成、持久化与页面检查

最终报告、分支数量和取样值见下方验收结果。模型调用不以Mock代替；同attemptKey回读同任务，错误revision409。GET读取及页面刷新不新增任务；新报告生成期间有可观察状态。

真实Signer会话：29.17秒，2637字符，1301个token事件、1个evidence事件及1个done事件，6条证据；done正文与历史一致。token事件数是SSE增量事件，不是模型计费Token数。历史恢复保留方法附近的证据窗口，修正尾换行造成的范围越界。回答仍偏长，适合作为主动深入请求的结果，不能据此证明默认讲解适合每个新手。

Edge实际操作覆盖：Python概要、模块选择与刷新、折叠术语、非Java源码入口、焦点循环/Escape/回焦；会话稳定地址、历史、引用定位、Python/测试/文档标签及下一片段；Java静态链、断点与业务模块对应、分支展示。截图和脱敏摘要放在仓库外`~/.codex/reviews/devmate-ai/2026-11-13/`，不提交原始模型响应、源码快照或认证文件。

- 修改前：后端265项、前端154项通过。最终：后端285项、前端166项通过，生产构建、Skill结构校验及`git diff --check`通过。
- 后端自动检查覆盖输入、权限、幂等、并发、模型异常、取消、旧JSON兼容、分支校验、真实位置、长片段/UTF-16分页。H2/Mock用于回归，不冒充MySQL或模型效果。

- 发现并修复的额外问题包括：接口声明类型遗漏、精确调用与定义混排、取样被长注释占满、历史回读丢聚焦窗口，以及模型Schema不接受终止边null。测试先复现关键故障再验证修复。

本轮曾将Maven测试和启动编译同时写同一target，造成暂态类缺失；已改为顺序执行并用干净构建回归，未删改功能或削弱测试来绕过。

## 可复现步骤与局限

按启动手册使用MySQL启动DevMate，导入表中固定快照；显式生成导览。记录Prompt/策略/检索版本、账户模型、任务ID和状态；用表中三题及相同预算检索，核对定义、真实行号和来源。打开保存报告，依次选择模块、刷新地址、引用与续读；最后检查无权限和错误版本。付费调用次数应独立记录，不能把同键重放计为新生成。

本轮真实生成共四次（两次Python、两次Java）：先验收取样，随后分别修正预览窗口与分支Schema后复验；不挑选多次输出后只报最好的一份。若需要统计模型稳定性，应预先固定数据集和重复次数，再单独获得调用预算。

未知范围仍包括：大型多仓/多应用系统的代表性、全部语言的结构分析、动态注入/反射/跨仓调用、手机完整流程、真实新人的理解耗时与复述正确性。Skill通用调查流程不等于全语言解析器；预算外内容必须保留未知，不能把缺证据判为项目未实现。

后续教学实验可预先定义“说出用途、找到指定模块、复述成功与失败、定位一句依据”四项任务，招募知情同意的初学者，对照旧技术列表与新导览，记录完成率、时间及错误类型；这只是实验方案，尚无真实成绩。

两份均为v7、runtime-first-v4。Python最终报告生成于终止Schema修正前，保留原结果，没有为追加终止边再次付费；Java复验使用修正后的转换器，库存不足和不能重复下单分别返回失败并结束。另有成功提前返回和后台异常结束。边的“结束”表示该分支结束，不全是失败。

终止边缺失的根因是Spring AI默认Java Schema将`Integer toStep`映射为仅integer。自定义输出转换器仅把此字段扩展为integer/null，服务端步骤/引用校验保持；新增测试直接验证模型收到的实际Schema，避免仅以Java DTO可空推断模型协议可空。
