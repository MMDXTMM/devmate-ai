# DevMate AI 项目总设计

## 1. 项目定位

**中文名：** DevMate AI 智能研发协作 Agent 平台  
**英文名：** DevMate AI — Intelligent Development Assistant Platform

一句话介绍：

> 基于 Java 与大模型构建的研发协作平台，通过 RAG 检索项目私有知识，并通过受控 Tool Calling 获取代码、文档、日志和 Git 变更信息，辅助研发人员理解系统和完成工程任务。

该项目用于证明两类能力：

1. 使用 Spring Boot、MySQL、Redis、MQ 等技术建设可靠业务系统的 Java 工程能力。
2. 使用 Agent、RAG、Embedding、Tool Calling 将大模型落地到真实研发流程的 AI 应用能力。

## 2. 为什么不是普通 AI 聊天

直接调用大模型只能基于已有上下文生成文本，无法自动获得企业私有源码和实时业务数据，也不能安全执行外部操作。

DevMate AI 的边界是：

- 大模型负责理解自然语言、规划步骤和选择工具。
- Java 负责权限、参数校验、事务、工具执行和安全边界。
- RAG 负责检索与问题相关的私有代码和文档。
- 任何高风险或确定性操作都不交给模型自由执行。

可以概括为：**AI 负责理解与规划，Java 负责可靠执行。**

## 3. 核心用户场景

### 3.1 代码理解

用户询问“登录流程在哪里实现”。系统检索相关代码，返回入口类、调用链和关键实现，并给出文件与符号来源。

### 3.2 需求分析

用户输入新需求。Agent 结合现有项目结构和团队规范，生成业务流程、接口建议、数据模型、风险点和实施清单。

### 3.3 Bug 诊断

用户提交异常堆栈或日志。Agent 定位异常位置，检索关联代码，区分事实、推断和待验证项，并给出排查步骤。

### 3.4 Git 变更风险分析

用户指定提交或差异内容。Agent 分析受影响模块、潜在回归范围和建议测试点。

### 3.5 企业技术规范问答

系统从架构文档、接口规范和编码规范中检索依据，避免模型凭空生成团队规则。

## 4. 第一版核心能力

### Agent

- 分析用户目标
- 判断是否需要外部信息
- 选择一个或多个工具
- 汇总工具结果
- 输出带来源、风险和不确定性的答案

### RAG

- 解析 Java 源码和 Markdown 等文档
- 按类、方法和语义边界切片
- 生成 Embedding
- 按项目和版本进行向量检索
- 将高相关片段提供给大模型

### Tool

首批计划：

1. `searchCode`：语义检索源码。
2. `searchKnowledge`：检索技术文档。
3. `analyzeStackTrace`：解析异常堆栈并定位符号。
4. `analyzeProjectStructure`：分析模块、包和依赖关系。
5. `analyzeGitDiff`：分析代码变更影响。
6. `getIndexTaskStatus`：查询异步知识库构建状态。

## 5. 数据职责

### MySQL

保存结构化业务数据：

- 用户与权限
- 接入的项目
- 文档元数据
- 索引任务
- 会话与分析记录
- AI 调用指标

### 向量存储

保存用于语义检索的代码和文档 Chunk。第一版先以易运行的方案验证 RAG，达到规模后再评估 Elasticsearch 或专用向量数据库。

### Redis（后续）

- 会话记忆
- 限流
- 短期缓存
- 分布式任务状态

### RabbitMQ（后续）

只处理耗时且无需同步等待的任务，例如代码仓库全量解析、批量 Embedding 和日志批处理。代码搜索、知识检索等即时交互继续使用同步调用。

## 6. 模块化单体结构

```text
com.devmate
├── common          通用响应、异常、基础配置
├── user            用户与权限
├── project         项目接入和管理
├── knowledge       文档/源码解析、切片、索引和检索
├── agent           Agent 编排、Prompt 和模型调用
├── tool            受控工具定义与执行
├── bug             故障分析记录
└── conversation    会话和 AI 调用记录
```

模块先通过 Java 接口协作，不跨模块直接操作对方的数据访问层。这样可以在保留单体开发效率的同时，为后续服务拆分建立边界。

## 7. 目标架构演进

第一阶段不使用 Spring Cloud。只有出现下列真实需求时才拆分：

- AI 调用耗时或并发与普通业务差异明显。
- 知识库构建需要独立扩容。
- 某个模块需要独立发布或故障隔离。

潜在拆分顺序：

1. `agent-service`
2. `knowledge-service`
3. `user/project-service`
4. Gateway、注册发现和服务治理

## 8. 安全与可靠性原则

- 模型不能直接连接数据库或执行任意 Shell。
- Tool 使用白名单能力、结构化参数和服务端权限校验。
- 检索必须按用户、项目和版本隔离。
- 所有模型调用设置超时、有限重试和降级提示。
- 答案区分“检索事实”和“模型推断”。
- API Key、密码和本地路径不进入 Git。
- 记录模型、Token、耗时、工具调用与失败原因，但不记录敏感源码全文。

## 9. 简历表达目标（完成功能后再使用）

> 基于 Spring Boot 与大模型构建智能研发协作 Agent 平台，通过 RAG 检索项目源码和技术文档，并使用 Tool Calling 调用代码搜索、异常定位与 Git 变更分析等受控能力；设计增量索引、异步知识库构建、调用日志和服务降级机制，提高私有知识回答的准确性与系统可用性。

注意：只把已经实现并能现场解释、演示和测试的能力写进简历。
