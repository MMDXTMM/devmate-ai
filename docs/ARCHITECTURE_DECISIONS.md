# 架构决策记录

## ADR-001：先模块化单体，后微服务

**状态：** 已接受

当前最重要的是验证项目管理、代码检索、RAG 和 Agent 的完整闭环。提前拆成多个网络服务会增加注册发现、配置、远程调用和分布式一致性成本，却没有带来已验证的收益。

模块之间仍应保持清晰边界，禁止跨模块直接依赖内部 Mapper，为未来拆分保留条件。

## ADR-002：Java 21 + Spring Boot 3.5

**状态：** 已接受

项目选择 Java 21 LTS。Spring Boot 3.5 仍支持 Java 21，并与当前 MyBatis-Plus 的 Boot 3 Starter 配合。暂不升级 Spring Boot 4，以降低学习期的第三方生态兼容成本。

## ADR-003：MyBatis-Plus

**状态：** 已接受

结构化业务数据需要明确的数据访问层。MyBatis-Plus 提供常用 CRUD 能力，同时保留自定义 SQL 的空间。不会把复杂业务查询硬塞进通用 CRUD。

## ADR-004：Flyway 管理数据库结构

**状态：** 已接受

Git 不适合保存数据库物理文件。通过版本化迁移脚本确保两台电脑、测试环境和未来云环境拥有一致结构。

## ADR-005：默认 H2，local Profile 使用 MySQL

**状态：** 已接受

默认 H2 让首次拉取、自动测试和基础演示不依赖外部服务。MySQL 仍是目标业务数据库，通过本地 Profile 启用。涉及 MySQL 特性的查询必须在 MySQL 环境补充验证。

## ADR-006：同步查询与异步任务分开

**状态：** 已接受

代码搜索和知识检索需要即时结果，使用同步调用。全量解析、批量 Embedding 和日志批处理耗时长，后续使用消息队列异步执行。不会为了“用了 MQ”而让全部 Tool 异步化。

## ADR-007：模型不能直接访问底层资源

**状态：** 已接受

模型只选择预定义 Tool。Java 服务对工具参数、权限、资源范围和超时负责。禁止模型直接访问数据库、执行任意 SQL 或 Shell。
