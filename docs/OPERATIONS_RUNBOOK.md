# DevMate AI 运维手册

## 1. 启动前检查

- 确认 Java 版本满足项目要求。
- 确认 MySQL 可连接且 `devmate` 数据库存在。
- 确认 `application-local.yml` 或生产环境变量未提交 Git。
- 私有仓库导入时确认 Git 凭证仅具有必要的只读权限。
- 执行真实 AI 审查时确认 `DASHSCOPE_API_KEY` 只存在于运行环境。
- 确认 `workspace/` 有足够磁盘空间并且不位于 Git 跟踪范围。

## 2. 启动与验证

开发环境：

```bash
./mvnw spring-boot:run
```

验证：

```bash
curl http://localhost:8080/api/health
curl http://localhost:8080/actuator/health
```

前端：

```bash
cd frontend
npm run dev
```

不要以“进程存在”作为唯一成功标准；还要确认健康接口、数据库迁移和关键业务查询成功。

## 3. 正常停止

优先向 Spring Boot 进程发送正常终止信号，让优雅停机释放端口和数据库连接。不要强制结束仍在写数据库的任务，除非正常停止超时。

停止后检查：

- 8080 端口已释放。
- `RUNNING/INDEXING` 任务是否需要标记中断或重新执行。
- 日志中是否存在未完成迁移或数据写入错误。

## 4. 常见故障

### 后端无法启动

依次检查：

1. 8080 端口是否被占用。
2. MySQL 是否运行。
3. 数据库账号、密码和库名是否正确。
4. Flyway 是否报告迁移校验失败。
5. 使用的 JDK 是否兼容。

### DataGrip 有数据但接口查不到

- 确认应用和 DataGrip 连接的是同一个数据库。
- 确认应用激活 `local` Profile，而不是测试 H2。
- 确认 BIGINT ID 没有经过 JavaScript 数字转换。
- 确认记录没有被逻辑删除。

### Git 源码导入失败

- 查看最近 `index_task.error_message`。
- 检查仓库 URL、默认分支和仓库可见性。
- 私有仓库确认 Token 未过期且具有目标仓库 Contents Read-only 权限。
- 检查工作目录权限、磁盘空间、文件数量和容量限制。
- 失败任务可以重新执行，不要手工把项目状态直接改成 `READY`。

### 任务长期停留在运行中

- 确认应用是否在任务期间异常退出。
- 根据任务开始时间、日志和工作目录判断是否仍在执行。
- AI 审查任务在再次提交时会把超过 10 分钟的旧 RUNNING 任务标记为失败并释放幂等键。
- 其他当前同步任务仍需根据状态人工重新发起；异步阶段将增加租约、心跳和超时恢复。

### AI 审查失败

- 先查询最近 `ai_review_task`，确认前置 Diff 和静态分析属于同一 revision。
- 检查 `ai_invocation_log` 的 provider、模型、Token、耗时和脱敏错误，不查询或输出完整 Prompt。
- “未配置AI审查模型API Key”表示启动后端的进程没有读取到 `DASHSCOPE_API_KEY`。
- 超时或远端错误可以重试；权限和配置错误应先修正，不要无限重试消耗额度。
- `rejected_findings` 大于 0 表示模型返回项未通过 Chunk 或结构校验，不应手工绕过校验写入 Finding。
- Agent 模式额外查询 `tool_call_log` 的步骤、状态、耗时和脱敏错误；不要尝试恢复完整参数或源码输出。
- “Agent未获得可验证的代码检索证据”表示模型没有成功调用 `searchCode`，系统已按安全策略停止最终审查。
- “重复调用同一工具超过上限”或“工具调用次数超过上限”通常表示模型规划循环；先保留审计链分析 Prompt，不要盲目提高限制。
- 工具超时只终止该只读步骤；未知工具和非法参数会记录失败，模型可在剩余步数内纠正。

### 审查反馈无法保存或无法恢复

- 确认 Flyway 当前版本至少为 V12，并且存在 `code_review_feedback` 表。
- 确认请求路径中的项目和 Finding 属于同一个项目；跨项目请求会统一返回不存在。
- 反馈类型只能是 `ACCEPTED/REJECTED/FALSE_POSITIVE/DEFERRED`，备注最多 1000 字。
- 当前每个 Finding 只保留一条最新反馈；重复 `PUT` 会更新原记录，不会新增历史版本。
- 保存反馈不会重新运行模型。如果出现模型调用或 Token 增长，应先检查前端是否错误触发了审查执行接口。

### 审查评测无法创建或指标不完整

- 确认 Flyway 当前版本至少为 V13，并存在 `review_evaluation_case/review_evaluation_run`。
- 用例必须绑定同项目、同目标 revision 的成功 Diff；`DEFECT` 必须提供类别、相对文件和有效行区间。
- 同一数据集只能是一个 `CLEAN` 对照或一组 `DEFECT`，不能混合。
- 评测只能绑定成功 AI 审查；执行模式来自服务端任务快照，不能由客户端指定。
- `partialResult=true` 表示出现候选歧义，相关项已进入人工复核且未计入 TP/FP/FN；不要手工篡改指标。
- 重复提交相同 AI 任务和数据集会返回原运行，不会重复统计或再次调用模型。

## 5. 日志检查

排障时使用 `requestId/projectId/taskId` 关联请求、项目和任务。重点观察：

- 启动版本和激活 Profile。
- Flyway 当前版本。
- 外部调用耗时和错误类别。
- 项目与任务状态转换。

禁止把包含 Token、密码或私有源码的日志发送到公开 Issue 或提交到 Git。

## 6. 数据库与备份

- 结构变更前备份数据库，并在非生产环境验证恢复。
- Flyway 迁移执行后不修改原脚本。
- 删除或重命名字段采用“新增兼容 → 迁移数据 → 切换代码 → 后续删除”的分阶段方案。
- 定期检查失败任务、逻辑删除数据和增长较快的日志表。

## 7. 密钥轮换

轮换 Git/LLM Token 时：

1. 创建权限更小的新 Token。
2. 更新运行环境并重启应用。
3. 验证一次只读调用。
4. 撤销旧 Token。
5. 检查日志和 Git 历史中没有密钥。

一旦 Token 出现在聊天、日志或 Git 中，必须立即撤销，不能仅通过删除消息解决。

## 8. 发布与回滚

发布前：测试、前端构建、数据库迁移检查、配置检查和备份全部通过。

回滚时区分：

- 仅代码变化：回滚应用版本。
- 向后兼容数据库变化：旧应用仍可运行。
- 破坏性数据库变化：使用事先验证的数据恢复或反向迁移方案。

每次发布记录 Git revision、数据库版本、配置项名称变化和验证结果，不记录配置值。
