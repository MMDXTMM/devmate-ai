# 通俗项目导览：产品接入与验收

日期：2026-11-11。JSON 外层版本 `project-guide-v1`，当前默认 Prompt 为 `src/main/resources/prompts/project-guide-v6.txt`；旧 v1/v2/v3/v4/v5 保留兼容。对应独立提示词、通用方案和 project-guide skill，由 Spring AI 补充固定 Content JSON Schema；不是把包含文件工具假设的独立 Markdown 原样交给模型。

## 交付范围

- 新导入允许没有 Java 的文本仓库。白名单覆盖常见源码后缀、README/文档和构建清单；Java 仍使用原 AST，YAML/Properties 及迁移 SQL 保留原结构解析。通用文本使用 `TEXT_EXCERPT`，不伪造符号或调用关系。
- 已导入快照按说明/清单、入口、实现、模型、配置、测试及子项目分组抽样。Java 排除 import 片段，优先取业务方法。模型按用户目标归纳能力，不能直接把技术目录视为业务模块。
- 工作台首页默认展示用途、受众、场景、主要能力和 1～3 条代表流程。点击后才显示参与者、输入输出、规则和结果；继续点击“查看实现依据”才渲染文件与代码。“理解项目业务”只提供 Java 实现、接口与高级文件结构，避免重复新人导览。源码统计与审查操作移入高级分析。
- 新会话保存 `project-conversation-v3`，采用三层解释原则。已保存 v1/v2 会话沿用自身版本；模块和流程的已验证 Chunk 引用可作为聊天检索种子，仍须重新检索并引用本轮证据。聊天保留原有 SSE、历史、停止及账户模型能力。

## API 与数据契约

继续复用 `POST /api/projects/{id}/understanding-reports` 和 `GET .../latest`。请求仍为 `{revision, attemptKey}`，新增可选查询参数 `background=true`：HTTP 200 返回持久化的 RUNNING 任务，通过 latest 查询终态；默认 false 保留同步兼容。模型调用前后沿用短事务和任务状态；同用户、同 attemptKey 不会再调用模型。

响应保留原字段，增加可空 `guide`：

- `schemaVersion`：宿主固定为 `project-guide-v1`。
- `snapshot`：宿主提供 Git revision、已索引文件内容哈希摘要及读取策略版本。当前只导入远程 Git 快照，不读取本地工作树，不能把它称为工作树快照。摘要最多包含本轮列出的 3000 个索引文件。
- `content`：模型返回的 `project/modules/flows/glossary/openQuestions`；具体 DTO 见 `ProjectGuide.java`，前端类型同名。模块关系、流程所属模块使用字符串逻辑 ID。
- `coverage`：实际索引/取样数量、字符数、预算和限制，由 Java 计算，模型不得填写覆盖率。
- `evidence`：宿主提供 ID、来源类型、revision、真实文件/符号/行号及有限代码预览。

`conclusionStatus` 为 `OBSERVED/INFERRED/UNKNOWN`；`implementationStatus` 为 `IMPLEMENTED/PARTIAL/PLANNED/UNCLEAR`。两者独立：文档可以被直接观察，但其承诺不等于功能已经实现。源码观察也不表示已运行验收。

主要校验包括：必填文本和集合、长度/数量上限、合法枚举、模块/流程 ID 唯一、模块交叉引用、证据属于本次实际读取集合、重复引用和非 UNKNOWN 结论缺失引用。无效结果拒绝保存为成功；不静默删除非法引用后继续宣称成功。该校验能验证结构和来源，不能自动证明模型每句话的语义正确。

主要失败：无可读证据或版本变化/并发 409，越权 403，未认证 401，模型、超时或输出契约失败保存 FAILED 并返回脱敏错误。最新报告按当前用户、项目和时间查询，避免混用其他成员的模型报告。

前端网络响应丢失时保留生成幂等键；明确的 HTTP 失败允许下一次重新生成。切换项目/关闭窗口时清理键与异步结果。读取报告不触发付费调用。

## 持久化与兼容

不新增表或迁移，复用 V24 `report_json` 保存版本化结构、宿主元数据及证据引用，源码正文不重复保存。回读按项目和 revision 从 KnowledgeChunk 回填预览。旧 JSON 缺少 `guide` 时按旧契约显示。

Java AST `source-structure-v2` 语义保持；新增文本片段另带 `text-excerpts-v1` 元数据。历史 Java 快照不会被静默改写。相同 revision 的普通导入仍幂等跳过；获取新增文本范围需要远端新 revision，或在既有重建保护允许时显式重建。已有报告/对话引用阻止的重建不会绕过，不能为了新导览删除历史证据。

## 实际资源与安全边界

- 导入沿用隔离目录、路径根校验、拒绝符号链接、单文件与总字节限制。新增 `devmate.source.max-text-files` 默认 1500，保留 Java/配置/迁移的原有独立上限。
- 跳过已知依赖、产物、凭据目录/文件、本地配置、NUL 二进制与非法 UTF-8。文本片段按真实行切分，常见字面量凭据脱敏；不承诺能识别源码里任意形式的秘密。
- 报告最多列出 3000 个索引文件、给模型前 150 个路径、检查 150 个文件；默认最多 40 个证据、48000 个代码字符，每个文件最多两个片段，每段最多 1800 字符。配置有硬上限。超预算如实标注，未读取内容不能成为事实依据。
- 仅从授权导入快照读取，模型不获得目标脚本、Shell、SQL 或任意文件访问。报告读取不等于全仓分析、编译或测试执行。
- 当前使用一次有界抽样后生成，尚未实现方案中建议的四个通用按需读取 Tool、自动反复调查或 MCP 服务；其他语言 AST/引用定位与新人两分钟用户研究仍待后续。

## README 优先与非 Java 文件验证

默认 Prompt 升级为 `project-guide-v3`，抽样策略记录为 `readme-first-v2/text-excerpts-v1`。输入、状态、失败响应与数据库结构保持兼容：

1. 从当前用户授权的已导入快照寻找 README；大小写不敏感，优先根目录，根目录标准 README.md 优先于翻译变体。缺少根说明时选择路径最浅的 README，支持 md/markdown/rst/txt/adoc 和无后缀 README。
2. 主要 README 先于清单和源码查询，最多四个片段、每段最多 1800 字符；存在其他文件时 README 使用不超过总字符预算的三分之一且最多 7200 字符。其余文件仍最多两个片段并按实现角色轮转，总字符/片段上限不变。
3. 模型输入明确分成“README 项目介绍”和“实现核对证据”，不重复传递同一片段。先理解用途和受众，再用代码核对；宣传、计划和未读到的实现不能标成已完成，文档冲突写入未知项。
4. README 缺失或没有可读正文时如实说明并使用其他证据；不跟随 README 链接、不执行其中命令。历史仅含 Java 的索引不静默补写；旧报告继续读取，用户点击“重新分析”才使用新 Prompt，首次缺少导览沿用原有自动生成流程。

| 文件范围 | 当前能力与验证方式 |
| --- | --- |
| Java | 保留 AST 符号、调用引用和 Java 审查；完整回归覆盖 |
| Python、JavaScript/TypeScript、Go | 通用文本导入、行号与源码预览；真实仓库验收记录见下文 |
| Vue、Rust、C++、C#、HTML、CSS | 合成文件测试验证白名单识别、文本片段与真实行号；未宣称真实仓库深度准确率 |
| README、Markdown/RST、JSON/TOML 清单 | 文档/清单文本读取与引用；不是源码实现证明 |
| YAML、Properties、迁移目录 SQL | 沿用原结构解析；普通 SQL 文件不在迁移识别范围内 |

其他源码后缀支持范围以 `SourceFileType` 为准，只有 Java 使用 AST。通用文本读取不提供其他语言的确定调用图、编译或运行验收。不读取二进制和非法 UTF-8；安全目录、字节预算和凭据过滤继续生效。

### 内容驱动的 AI 图标（替代关键词匹配）

用户确认图标需要随未来导入的项目内容适配，因此移除前端业务关键词表。默认 Prompt 升级 `project-guide-v4`：同一次 README 优先、源码核对的导览分析中，根据整体用途选择项目图标，根据模块职责/能力/输入输出选择模块图标，不按名称硬套、辅助模块或列表顺序推断项目类型。

接口采用兼容性追加字段：

```json
{
  "guide": {
    "content": {
      "appearance": {
        "projectIcon": "🔭",
        "modules": [{ "moduleId": "spectral", "icon": "🌈" }, { "moduleId": "tracking", "icon": "🛰️" }]
      }
    }
  }
}
```

- `appearance` 可空，`appearance.modules` 只保留本报告真实模块 ID，使用显式 moduleId/icon 列表而非动态键对象；最早实验版 moduleIcons 可回读。服务端只接受单个 Unicode emoji（含组合 emoji），不接受 URL、HTML、SVG 或说明文字；无效装饰回退，不使有效业务报告失败，原证据/状态校验不放宽。
- 沿用 V24 `report_json` 保存，未新增迁移。旧 v1/v2/v3 报告继续回读；不会只为补图标自动重跑付费分析。用户可以点击“重新分析”更新旧报告。
- 项目分页/详情响应新增可空 `icon`，批量读取当前账户、当前源码 revision 的最新成功报告，过滤非成员及已删除项目；不为每张卡请求整份源码证据，不触发模型。返回首页刷新项目列表，带回刚保存的图标。
- 首次导入、尚未生成导览时显示中性 📁，模块无图标显示 🧩；首次进入理解工作台生成导览后复用 AI 保存结果。首页、导览头部、模块卡片、详情及业务地图保持一致；名称、模块关系和实现结论不由图标决定。
- 测试通过“名称与内容不同”“未登记的天文领域图标”“旧报告”“非法图标”“同键重放”“其他账号/旧版本/失败/删除隔离”等场景，Spring AI Mock HTTP 验证新版结构转为 DTO，Mock 不证明实际模型语义选择总是正确。

验证：后端 248 项、前端 147 项测试、生产构建、差异检查通过。本地 MySQL 用原账号的 5 个可见项目执行相同批量查询，通过且无写入。真实模型和页面观感分别记录，不能将 Mock 或字符校验当成语义正确率。

## 2026-11-12：后台生成与超时诊断

- 默认报告模型读取上限统一为 180 秒（Java Properties 和 application.yml 一致），连接上限仍为 5 秒；审查与聊天的独立配置不变。延长等待不是保证供应商一定成功。
- 工作台提交使用 `?background=true`，完成权限、固定 revision 抽样及当前账户模型快照捕获后，短事务保存 RUNNING，再交给有界本机线程池（2 个工作线程、2 个等待位置）。模型调用不占用数据库事务或请求线程。任务执行不依赖后台线程中的登录上下文，避免串用账户凭据。
- 排队满保存 FAILED/QUEUE_FULL、释放 running_key，并返回脱敏 409；后台模型或契约失败保存 FAILED，轮询返回 errorMessage。旧同步入口继续支持，重复 attemptKey 返回同一任务，不再次排队或调用模型。
- 页面说明通常等待 1～3 分钟、可能排队；3 秒查询一次，最多 220 次，不重复提交；离开页面停止查询，已提交的后台任务继续。失败后由用户决定重试，不自动循环付费。
- 进程重启后内存队列不能恢复执行；latest 查询和新任务准备时将超过 10 分钟的 RUNNING 标记为 STALE_TASK/FAILED，释放占位，不永久卡住。尚未实现跨进程持久任务队列。
- 区分嵌套 Socket/HTTP/通用超时和连接失败、401/403、429。导览校验错误显示宿主字段位置及规则（例如 modules[0].input 必填为空），不显示模型原文、非法引用值、SQL 或凭据。
- Prompt v5 补充文字/数组上限、非空字段及引用规则；v6 继续保留 README 优先、源码核对与语义图标，同时只向模型提供本次证据短编号 E1/E2…。Java 严格映射回实际字符串 Chunk ID，再校验业务结构并持久化。未知、跨本轮或重复引用仍失败；不替换自然语言正文，不改历史报告和外部 API ID。旧版本文件保留。
- 回归覆盖后台立即返回、账户模型快照、任务失败落库、重复提交、队列拒绝、轮询恢复、停止查询、错误分类、脱敏字段诊断和证据短编号映射。真实模型结果与最终测试数量另记项目日志。
