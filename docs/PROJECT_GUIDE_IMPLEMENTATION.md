# 通俗项目导览：产品接入与验收

日期：2026-11-11。实现版本 `project-guide-v1`；对应独立提示词、通用方案和 project-guide skill。运行时使用 `src/main/resources/prompts/project-guide-v1.txt`，由 Spring AI 补充固定 Content JSON Schema；不是把包含文件工具假设的独立 Markdown 原样交给模型。

## 交付范围

- 新导入允许没有 Java 的文本仓库。白名单覆盖常见源码后缀、README/文档和构建清单；Java 仍使用原 AST，YAML/Properties 及迁移 SQL 保留原结构解析。通用文本使用 `TEXT_EXCERPT`，不伪造符号或调用关系。
- 已导入快照按说明/清单、入口、实现、模型、配置、测试及子项目分组抽样。Java 排除 import 片段，优先取业务方法。模型按用户目标归纳能力，不能直接把技术目录视为业务模块。
- 页面默认展示用途、受众、场景、主要能力和 1～3 条代表流程。点击后才显示参与者、输入输出、规则和结果；继续点击“查看实现依据”才渲染文件与代码。旧报告与 Java 静态导览放入折叠的高级入口。源码统计与审查操作移入高级分析。
- 新会话保存 `project-conversation-v3`，采用三层解释原则。已保存 v1/v2 会话沿用自身版本；模块和流程的已验证 Chunk 引用可作为聊天检索种子，仍须重新检索并引用本轮证据。聊天保留原有 SSE、历史、停止及账户模型能力。

## API 与数据契约

继续复用 `POST /api/projects/{id}/understanding-reports` 和 `GET .../latest`。请求仍为 `{revision, attemptKey}`，模型调用前后沿用短事务和任务状态；同用户、同 attemptKey 不会再调用模型。

响应保留原字段，增加可空 `guide`：

- `schemaVersion`：宿主固定为 `project-guide-v1`。
- `snapshot`：宿主提供 Git revision、已索引文件内容哈希摘要及读取策略版本。当前只导入远程 Git 快照，不读取本地工作树，不能把它称为工作树快照。摘要最多包含本轮列出的 3000 个索引文件。
- `content`：模型返回的 `project/modules/flows/glossary/openQuestions`；具体 DTO 见 `ProjectGuide.java`，前端类型同名。模块关系、流程所属模块使用字符串逻辑 ID。
- `coverage`：实际索引/取样数量、字符数、预算和限制，由 Java 计算，模型不得填写覆盖率。
- `evidence`：宿主提供 ID、来源类型、revision、真实文件/符号/行号及有限代码预览。

`conclusionStatus` 为 `OBSERVED/INFERRED/UNKNOWN`；`implementationStatus` 为 `IMPLEMENTED/PARTIAL/PLANNED/UNCLEAR`。两者独立：文档可以被直接观察，但其承诺不等于功能已经实现。源码观察也不表示已运行验收。

主要校验包括：必填文本和集合、长度/数量上限、合法枚举、模块/流程 ID 唯一、模块交叉引用、证据属于本次实际读取集合、重复引用和非 UNKNOWN 结论缺失引用。无效结果拒绝保存为成功；不静默删除非法引用后继续宣称成功。该校验能验证结构和来源，不能自动证明模型每句话的语义正确。

主要失败：无可读证据或版本变化/并发 409，越权 403，未认证 401，模型、超时或输出契约失败保存 FAILED 并返回脱敏错误。最新报告按当前用户、项目和时间查询，避免混用其他成员的模型报告。

前端网络响应丢失时保留生成幂等键；明确的 HTTP 失败允许下一次重新生成。切换项目/关闭窗口时清理键与异步结果。读取报告不触发付费调用。

## 持久化与兼容

不新增表或迁移，复用 V24 `report_json` 保存版本化结构、宿主元数据及证据引用，源码正文不重复保存。回读按项目和 revision 从 KnowledgeChunk 回填预览。旧 JSON 缺少 `guide` 时按旧契约显示。

Java AST `source-structure-v2` 语义保持；新增文本片段另带 `text-excerpts-v1` 元数据。历史 Java 快照不会被静默改写。相同 revision 的普通导入仍幂等跳过；获取新增文本范围需要远端新 revision，或在既有重建保护允许时显式重建。已有报告/对话引用阻止的重建不会绕过，不能为了新导览删除历史证据。

## 实际资源与安全边界

- 导入沿用隔离目录、路径根校验、拒绝符号链接、单文件与总字节限制。新增 `devmate.source.max-text-files` 默认 1500，保留 Java/配置/迁移的原有独立上限。
- 跳过已知依赖、产物、凭据目录/文件、本地配置、NUL 二进制与非法 UTF-8。文本片段按真实行切分，常见字面量凭据脱敏；不承诺能识别源码里任意形式的秘密。
- 报告最多列出 3000 个索引文件、给模型前 150 个路径、检查 150 个文件；默认最多 40 个证据、48000 个代码字符，每个文件最多两个片段，每段最多 1800 字符。配置有硬上限。超预算如实标注，未读取内容不能成为事实依据。
- 仅从授权导入快照读取，模型不获得目标脚本、Shell、SQL 或任意文件访问。报告读取不等于全仓分析、编译或测试执行。
- 当前使用一次有界抽样后生成，尚未实现方案中建议的四个通用按需读取 Tool、自动反复调查或 MCP 服务；其他语言 AST/引用定位与新人两分钟用户研究仍待后续。
