# 项目类型与读取策略

语言是选择读取工具的线索，不是报告的业务结构。下表是开放的入口提示，不是支持白名单。新类型沿“使用者/调用方 → 输入 → 处理 → 输出”继续调查。

| 观察到的类型 | 优先读取 | 先讲清的事情 | 不能擅自补出的能力 |
|---|---|---|---|
| Web 后端 / 服务 | 路由或协议注册、处理逻辑、数据/外部服务访问、相关测试 | 发出什么请求，如何处理，返回什么 | 无代码支撑的接口、表、权限、事务 |
| 前端 / 全栈 | 页面/路由、事件、状态、API 客户端；服务端存在时继续追踪 | 用户看到什么、操作什么、结果如何呈现 | 仅凭请求或按钮认定支付、落库或鉴权已实现 |
| CLI / 自动化工具 | 命令注册、参数、主函数、文件读写、错误处理 | 输入命令/文件后经过什么转换，生成什么 | HTTP、数据库或线上部署 |
| SDK / 通用库 | 公共导出、调用样例、核心实现、测试 | 调用者通过哪些能力解决问题，各能力如何合作 | 登录、订单等产品业务；样例调用等于生产使用 |
| 数据 / AI / Notebook | 数据入口、转换、训练/推理、任务编排、输出样例 | 数据从哪里来，如何处理，最终得到什么 | 模型效果、真实数据规模、训练已运行或线上效果 |
| 移动端 / 桌面端 | 启动和页面、事件、状态、本地存储、平台/网络桥接 | 用户如何完成任务，离线和外部依赖在哪里 | 服务端不可见的实现、平台桥接内部行为 |
| 游戏 / 交互程序 | 场景、事件/输入、状态、核心更新循环、资源声明 | 玩家做什么，状态和结果如何变化 | 二进制资源内部含义、服务器规则、实际帧率 |
| 嵌入式 / 硬件 | 启动、事件/中断注册、任务、协议、设备抽象、测试 | 接收什么信号，如何决策，输出什么动作 | 真实硬件时序、安全认证、设备已经验证 |
| 基础设施 / 配置 | IaC、部署拓扑、流水线、模块输入输出 | 准备哪些环境，怎样发布和连接 | 配置已部署、云资源真实存在或具有公网权限 |
| 文档 / 设计项目 | 目录、目标、角色、流程图、方案状态 | 描述或计划了什么，知识如何组织 | 文档描述的系统已经实现 |
| 混合 / 多仓工作区 | 各子项目清单、实际接口/导入/配置关系 | 每个子项目承担什么，如何组成整体 | 仅凭同名目录断言它们已打通 |

可查看的清单包括 `package.json`、`pyproject.toml`、`go.mod`、`Cargo.toml`、`pom.xml`、`build.gradle*`、`*.csproj`、`Gemfile`、`composer.json`、`pubspec.yaml`、`CMakeLists.txt` 等，按实际文件选择，不要求穷举。

## 能力分级

- **文本可读**：多数语言可通过说明、入口与实现片段做业务导览；明确读取覆盖和推断。
- **结构增强**：宿主提供 Tree-sitter、LSP、AST 或框架适配时，利用已验证符号和引用增强下钻；不因此声称识别了全部运行时行为。
- **证据不足**：只有二进制、图片、加密/严重混淆源码、不可访问子仓时，说明已读内容及缺口。OCR、反编译、运行和新下载都不作为默认前提。

大型项目按“各子项目侦察 → 主要能力候选 → 每个候选的代表性入口与实现 → 综合导览”推进。若预算无法核实某个候选，在覆盖信息中标记待分析，不能从报告中悄悄消失。
