# 项目问答的按需取证与上下文改进

## 范围和契约

2026-11-17，在现有模块化单体上改进项目理解，不更改账号、导入、审查或生成的既有资源路径，不新增数据库、依赖或迁移。现有未提交的生成/导览功能继续保留。

输入仍为项目对话中的 question/attemptKey；身份、projectId、revision、模型连接从已授权的会话确定，模型不能选择账号、外部地址、Shell或SQL。

输出继续 SSE 的 message/evidence/token/done/failed；新增可忽略的 `context` 事件，完成消息可选新增 `context`：

```json
{"actions":[{"tool":"read_code","status":"SUCCEEDED","evidenceCount":3}],"warnings":["代码证据达到总预算，部分内容未加入上下文"],"memoryUsed":false}
```

actions 是宿主记录的执行摘要，不是模型思维链；不保存工具参数、完整工具输出或完整 Prompt。状态包括 SUCCEEDED/REJECTED/REPEATED。旧客户端可忽略新增字段及事件。

`conversation_message.evidence_json` 新消息保存 `{evidence:[{chunkId,startLine,endLine,characters}],context:{...}}`，不重复保存源码；读取继续兼容原字符串 ID 数组及证据指针数组。没有修改已执行迁移。回读定位以原 Chunk 为准。

## 一：定位完整索引，再限制候选

`lexical-graph-v3` 先在 MySQL 当前项目/revision 中用绑定参数 LOCATE 查询目标符号、文件路径和关键词，再执行有界 Java 排序；显式文件和目标所属符号优先。关键词候选仍有1000条上限，不能宣称所有匹配项均已分析。它消除了无关Chunk先占满导入顺序窗口的问题，不是全文倒排索引。

预算现在依据实际发送的预览计算，防止长方法因完整正文超预算而在读取工具介入前被整体丢弃。字符/Token比采用保守近似，仍不是模型计费 Tokenizer。

向量以256条为一批按 vector_id 游标读取，优先队列只保留Top-K候选，默认最大扫描50000条；达到安全上限明确提示。MySQL仍保存 vector_json，Java线性计算余弦，不是ANN或专用向量库。

LOCAL仍是哈希向量。已有DashScope真实Embedding接口和环境配置继续复用（见VECTOR_RAG.md）；不把聊天模型Key自动当Embedding凭据，不自动切换或付费重建索引。真实语义召回效果需配合可用Embedding账号另行评测。

## 二：聊天按需补证据，再流式回答

`ConversationEvidenceResearch` 是只读服务，默认最多3次工具请求、35秒取证总时限、24000字符证据预算、最多20段。初始证据从原Chunk补读最多3000字符，按需读取每次最多8000字符，可通过真实行区间读取长方法后半段；Unicode边界、行号和项目/revision由Java校验。

三个模型工具：

- search_code(query)：当前项目、固定版本再次检索；
- read_code(chunkId,startLine?,endLine?)：读取真实代码区间；
- related_code(chunkId)：只加入明确的一跳INCOMING/OUTGOING关系证据。

Spring AI 使用当前会话模型快照和受控工具定义，关闭内部自动工具执行，由Java执行。异步取证传递请求的认证快照，每次工具检查成员权限；拒绝跨项目、跨revision、未知字段、非法行号和未知工具。相同工具与参数只执行一次。

达到预算、参数失败、模型不支持Tool Calling或取证超时，保留已取得证据，明确覆盖限制后流式回答；不自动无限重试。最终流式模型失败仍保存FAILED。停止时取消取证订阅/输出订阅，完成与取消复用既有状态机和幂等约束。同步HTTP客户端已经发出的请求可能仍等待自身超时，取消不保证上游不计费。

新对话默认 `project-conversation-v4`，旧会话Prompt版本保留。v3/v4均保留分层新人解释，v4加入取证约束和覆盖提示。模型回答区分源码观察、推断和待验证，静态阅读不等于运行验证。

## 三：多轮上下文

最近消息按完整成功的问答对携带，并设置20000字符预算；不带入FAILED/CANCELLED回答及对应用户问题，不让孤立ASSISTANT消息进入历史。当前问题不会被截断。

连续“继续”等追问从最近40条已完成消息找最近实质主题，明确符号仍优先于旧主题。较长会话从最近100条成功消息提取有界用户问题主题，超出正文预算的问题也保留简短主题。主题为原用户提问摘录，不是模型生成的事实总结，也不是无限长期记忆；不能替代本轮代码证据。

## 四：业务与代码连在一起

业务流程每步增加可折叠的实现代码和“追问这一步”。默认保留业务解释，只有展开才挂载代码组件；按需续读复用原有权限和源码接口。定向追问只预填，不自动触发收费模型请求。覆盖提示与工具摘要在聊天中折叠显示，历史刷新后保留。

## 五：固定验证和边界

固定检索数据集：`src/test/resources/evaluation/retrieval-regression-v1.json`，四个合成用例在同revision上分别运行LEXICAL与LOCAL HYBRID，验证指标持久化和实现优先排序。这个小数据集是回归门禁，不是实际项目准确率证明。

额外测试覆盖：超过1000条的晚到符号/文件、长方法预算、分页向量尾页命中/扫描上限、长方法后半段读取、真实关系补证据、跨项目拒绝、重复调用、非法参数、超时降级、完整问答预算、连续追问、失败问题排除、证据持久化恢复、Spring AI工具协议、SSE兼容和Vue逐步展开。

当前仍未实现无限代码上下文、任意深度动态调用、自动运行目标仓库、模型事实真实性保证或长期语义记忆。真实MySQL及外部模型的运行验收与Mock/H2测试必须区分记录。
